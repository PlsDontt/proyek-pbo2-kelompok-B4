| Nama use case | Login |
| Aktor | Pemilik Kos, Petugas |
| Prasyarat | Aplikasi terpasang dan database MySQL berjalan. Akun pengguna sudah terdaftar, dengan kata sandi tersimpan dalam bentuk hash. |
| Alur utama | 1. Aktor membuka aplikasi. <br> 2. Sistem menampilkan halaman login yang berisi kolom username dan kata sandi. <br> 3. Aktor mengisi username dan kata sandi, lalu menekan tombol **Masuk**. <br> 4. Sistem memeriksa bahwa kedua kolom sudah terisi. <br> 5. Sistem mencocokkan username dan hash kata sandi dengan data akun di database. <br> 6. Sistem menentukan peran pengguna (Pemilik kos atau Petugas) dan mengatur hitungan percobaan gagal kembali ke 0. <br> 7. Sistem menampilkan menu utama sesuai peran. Pemilik Kos melihat seluruh menu. Petugas tidak melihat menu kelola data kamar dan laporan pendapatan. |
| Alur alternatif | **4a. Kolom username atau kata sandi masih kosong** <br> 1. Sistem menampilkan pesan: “Username dan kata sandi wajib diisi. Lengkapi kedua kolom, lalu tekan masuk.” <br> 2. Hitungan percobaan gagal tidak bertambah. Alur kembali ke langkah 3. <br> **5a. Kata sandi salah atau username tidak ditemukan** <br> 1. Sistem menambah hitungan percobaan gagal berturut-turut. <br> 2. Sistem menampilkan pesan: “Username atau kata sandi salah. Periksa kembali huruf besar dan kecilnya, lalu coba lagi (percobaan gagal ke-N dari 3).” <br> 3. Alur kembali ke langkah 3. <br> **5b. Percobaan gagal mencapai batas (3 kali berturut-turut)** <br> 1. Sistem menampilkan pesan: “Login gagal 3 kali berturut-turut. Aplikasi akan ditutup. Buka kembali aplikasi untuk mencoba lagi.” <br> 2. Sistem menutup aplikasi. Use case berakhir tanpa login. |
| Hasil akhir | **Berhasil:** Aktor sudah masuk dan melihat menu utama sesuai perannya. <br> **Gagal:** Aktor tetap belum masuk. Setelah 3 kali gagal berturut-turut, aplikasi tertutup. |
